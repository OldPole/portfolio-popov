# Kirill Popov — Portfolio

Личное портфолио frontend-разработчика: опыт, навыки, образование, проекты, скачивание CV и контактная форма. Дизайн вдохновлён [benoldham.dev](https://www.benoldham.dev/), реализация написана на Nuxt.

## Стек

Nuxt 4 (Vue 3, Nitro), TypeScript, PostgreSQL с драйвером `pg`, Tailwind CSS 4, Nuxt I18n, Color Mode, Nuxt Image, Zod и Resend. Локальный шрифт Manrope с латиницей и кириллицей (SIL OFL).

## Запуск

Рекомендуется **Node.js 24.22.2 LTS**, версия также указана в `.nvmrc`. Поддерживаемые версии: `^22.22.3 || ^24.15.0 || >=26.0.0`.

В новом окне терминала проверьте окружение:

```powershell
node --version
npm --version
```

```powershell
Set-Location -LiteralPath 'D:\Works\Vue (Nuxt)\Portfolio-Popov'
npm install
npm run db:setup
npm start
```

Откройте **http://localhost:3000**. Английский язык и тёмная тема включены по умолчанию. `npm run dev` — аналог `npm start`. Остановить сервер: `Ctrl+C`.

Если PowerShell запрещает запуск `npm.ps1`, используйте `npm.cmd install` и `npm.cmd start`; менять политику выполнения не требуется. Для чистой установки после клонирования используйте `npm ci`.

## PostgreSQL

Перед первым запуском создайте пустую базу PostgreSQL и роль с правом создавать в ней схему и таблицы. Для этого под администратором PostgreSQL выполните `CREATE ROLE portfolio_app LOGIN;`, задайте пароль командой `\password portfolio_app` в `psql` и выполните `CREATE DATABASE portfolio_popov OWNER portfolio_app;`.

Создайте `.env` из `.env.example`, если файла ещё нет. Укажите в нём `NUXT_DATABASE_URL` в формате `postgresql://portfolio_app:пароль@127.0.0.1:5432/portfolio_popov`. Для проекта можно использовать любой доступный порт PostgreSQL. Специальные символы в имени пользователя и пароле должны быть закодированы для URL.

На компьютере, где уже создан кластер `.local/postgres18`, подключение настроено на порт `55432`. Если локальный PostgreSQL остановится, запустите его из корня проекта:

```powershell
& 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D .local/postgres18 -l .local/postgres18.log -w start
```

`npm run db:setup` применяет SQL-миграции и загружает исходный контент. `npm run db:migrate` применяет только ещё не выполненные миграции, а `npm run db:seed` загружает исходные данные после миграций. Повторный запуск не перезаписывает записи. Каталог локального кластера и `.env` исключены из Git.

Nitro отдаёт данные на чтение через `GET /api/portfolio` (опыт, навыки, образование, языки и карточки проектов), `GET /api/portfolio/profile` (профиль, ссылки и SEO) и `GET /api/portfolio/projects/:slug` (страница и галерея проекта). Опыт, группы навыков, образование, языки и проекты хранятся отдельными записями с порядком и признаком публикации. Английские и русские тексты хранятся вместе в JSONB. Интерфейсные переводы лежат в `i18n/locales/`.

## Проверка в консоли

```powershell
npm run typecheck
npm run lint
npm run format:check
npm run build
npm run preview
```

`typecheck` проверяет TypeScript. `build` создаёт production-сборку без подключения к БД. `preview` запускает её локально и читает настройки из `.env`. Сначала остановите `npm start`, если он занимает тот же порт.

Для production-запуска собранного сервера передайте переменные `NUXT_DATABASE_URL` и `NUXT_PUBLIC_SITE_URL` в окружении и выполните `node .output/server/index.mjs`. Перед запуском примените миграции и загрузите исходный контент в нужную базу.

| Команда                     | Назначение                              |
| --------------------------- | --------------------------------------- |
| `npm start` / `npm run dev` | Разработка с обновлением при изменениях |
| `npm run build`             | Production-сборка                       |
| `npm run preview`           | Просмотр production-сборки              |
| `npm run typecheck`         | Проверка типов                          |
| `npm run lint`              | Проверка ESLint                         |
| `npm run lint:fix`          | Исправление ошибок ESLint               |
| `npm run format`            | Форматирование                          |
| `npm run format:check`      | Проверка форматирования                 |

Автотесты по текущим требованиям не добавлены. GitHub Actions проверяет ESLint, форматирование, типы и сборку, без деплоя.

Prettier отвечает за форматирование: отступы в два пробела, точки с запятой, строки до 80 символов, компактные Vue-атрибуты, LF и читаемые HTML-теги без переноса закрывающей скобки в соседний элемент. ESLint проверяет ошибки JavaScript, TypeScript и Vue; `eslint-config-prettier` отключает конфликтующие правила оформления. `.editorconfig` задаёт общие настройки редактора. Для исправления кода запускайте `npm run lint:fix`, затем `npm run format`.

## Страницы и компоненты

Навигация ведёт к разделам главной страницы по якорям: `#experience`, `#projects` и `#contact`. Навыки и образование остаются после опыта. Карточки проектов открывают страницы с описаниями и галереями. Старые адреса разделов перенаправляют на соответствующие якоря с сохранением языка.

`components/ui/Button.vue` используется для действий, ссылок-кнопок и иконок. Варианты: `primary`, `outline`, `ghost`, `text`; размеры: `default`, `small`, `icon`. Компонент выводит `NuxtLink` для `to`, обычную ссылку для `href` и нативную кнопку для действий. Hover, клавиатурный фокус и курсор заданы общими стилями.

## Контактная форма

Контактная форма уже вызывает `POST /api/contact`. Nuxt отправляет письма через Resend на `ipetr6828@gmail.com`. При ответе на письмо подставляется адрес посетителя. К письму можно приложить один файл PDF, PNG или JPG до 4 МБ. Размер и формат проверяются на сервере перед отправкой в Resend.

Для локальной проверки зарегистрируйтесь в Resend с адресом получателя и создайте [ключ с разрешением Sending access](https://resend.com/docs/dashboard/api-keys/introduction). В корне проекта выполните:

```powershell
Copy-Item .env.example .env
```

Если `.env` уже существует, отредактируйте его. Для первого письма укажите:

```dotenv
NUXT_RESEND_API_KEY=re_ваш_ключ
NUXT_CONTACT_FROM="Kirill Popov <onboarding@resend.dev>"
NUXT_CONTACT_TO=ipetr6828@gmail.com
```

Перезапустите `npm start`, отправьте сообщение через форму и проверьте почту. С `onboarding@resend.dev` получателем может быть только email аккаунта Resend. Если аккаунт зарегистрирован на другой адрес, подставьте его для теста. [Ограничения тестового отправителя Resend](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain).

Для опубликованного сайта подтвердите свой домен в Resend и замените отправителя на адрес на этом домене, например `portfolio@ваш-домен`. Добавьте переменные на хостинге в окружение сервера Nuxt. Укажите публичный адрес сайта в `NUXT_CONTACT_ALLOWED_ORIGIN` и `NUXT_PUBLIC_SITE_URL`, затем соберите проект. Ключ храните в серверном окружении или локальном `.env`. [Настройка домена в Resend](https://resend.com/docs/dashboard/domains/introduction).

Если отправка недоступна, форма показывает ошибку и предлагает написать напрямую на email. Сайт не хранит сообщения в своей базе или логах.

## SEO и скорость

- Главная и страницы проектов рендерятся на сервере на обоих языках. При новом запросе контент читается из PostgreSQL.
- Для каждой страницы заданы отдельные title, description, Open Graph и Twitter-метаданные.
- Canonical, hreflang, абсолютные ссылки для предпросмотра и `/sitemap.xml` используют `NUXT_PUBLIC_SITE_URL`. Пока адрес не задан, фиктивные ссылки с localhost не генерируются, а sitemap возвращает 503 с указанием недостающей настройки.
- `/robots.txt` разрешает обход страниц, исключает API и после настройки домена указывает sitemap. Карта включает главную и опубликованные проекты на обоих языках.
- На главной есть структурированные данные Person (JSON-LD).
- Фото оптимизировано в WebP, имеет адаптивные размеры и высокий приоритет загрузки. У изображений указаны размеры; скриншоты ниже первого экрана загружаются лениво.
- Шрифты хранятся локально. Латиница предзагружается на всех страницах, кириллица на русских. Если шрифт не успеет загрузиться к первому показу, страница сохраняет системный шрифт до следующей загрузки. Для статических ресурсов заданы Cache-Control, production-файлы сжимаются Brotli/gzip.

Локальный аудит выполняется по production-сборке, а не по `npm start`. Он не заменяет замеры после публикации: итоговая скорость зависит от хостинга, CDN, сети и устройства. Реальные Core Web Vitals и индексацию можно оценить после деплоя.

## Структура

```text
app/
  assets/css/        # Tailwind, переменные тем, стили
  components/
    layout/          # Header, Footer
    sections/        # Hero, Experience, Skills, Projects, Contact
    projects/        # Карточка проекта
    ui/              # Общая Button и иконки социальных сетей
  composables/       # Форма и язык данных
  layouts/           # Оболочка страниц
  pages/             # Главная и страницы проектов projects/[slug]
shared/              # Общие типы и утилиты
database/            # SQL-миграции и исходные данные
scripts/database.mjs # Запуск миграций и загрузка исходных данных
i18n/locales/        # Переводы en.json и ru.json
modules/             # Совместимость i18n с Windows-путями со скобками
public/
  cv/                # PDF резюме
  fonts/             # Шрифты и лицензия
  images/projects/   # Скриншоты
server/api/          # Чтение портфолио и POST /api/contact
server/utils/        # Подключение и запросы к PostgreSQL
.github/workflows/   # Проверка типов и сборки
```

В текущем пути есть скобки (`Vue (Nuxt)`). `windows-path-compatibility.ts` исправляет сопоставление путей в серверном преобразовании Nuxt I18n 10.6 на Windows. Он включается только для соответствующих путей и не изменяет зависимости.

## Git workflow

- `main` содержит актуальную завершённую версию портфолио.
- Для задачи создаётся одна feature-ветка от актуального `main`: `YYYY-MM-DD.feature-name`.
- Все изменения одной задачи сохраняются в этой ветке.
- Готовая feature-ветка вливается в `main` через `git merge --no-ff` с отдельным коммитом слияния.
- После успешного push в `main` завершённая feature-ветка удаляется локально и на GitHub.
- Коммиты: `feat: add ...`, `fix: correct ...`, `docs: describe ...`, `chore: configure ...`.

`.env`, зависимости, кэши и сборки исключены из Git. `.env.example` и `package-lock.json` сохраняются в репозитории.
